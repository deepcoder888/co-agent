# A-book runtime protocol v2

The Agent owns meaning, coverage decisions, prose and evaluation. The Python helper owns deterministic extraction, bounded views, immutable checkpoints and recoverable filesystem operations. It does not certify that a model understood the book.

## Invocation and placement
Run the installed synchronous helper with Python 3.11+:
`python -X utf8 -B ~/.codex/agent-support/a-book/abook_runtime.py --request <absolute-request.json>`.
Write each request as UTF-8 JSON with apply_patch in the authorized work directory, or pass JSON through stdin using `--request -`. CLI output is UTF-8 JSON. Exit 0 means the requested operation succeeded, exit 2 means a rejected request; an injected crash exits 86 only inside disposable test fixtures.
State lives at WORK_DIR/state.json. Package and work directories are separate non-overlapping paths; Agent target is an exact .toml outside both. Existing completed packages stay unchanged. Runtime fixtures and logs are not knowledge packages.

## Source contract
`inventory`: source, optional offset and limit (default 10, maximum 20); iterate until both linear_total and navigation_total are covered. Return EPUB title, ordered linear entries, navigation targets, entry hashes and code-point lengths. Inspect nav-only sections before deciding exclusions. XML/HTML textual extraction cannot prove visual diagrams are understood.
`init`: source, edition, package_dir, agent_path, work_dir and ordered sections [{id,title,entries,substantive}]. Optional run_id; test_fixture is false except in a test. Both new output targets must be absent; the work directory may contain request JSON but no state/journal. Reconcile every linear spine entry exactly once, including explicitly non-substantive sections; nav-only substantive material must be added explicitly. Init saves the source digest, extractor version, each entry's normalized offset interval and length before returning any source prose.
`read_unit`: work_dir and section_id. It selects the exact current offset, at most 6,000 code points, and caps the entire envelope at 24,000 UTF-8 bytes. The last field is receipt. Request output budget >=8,000 tokens. Inspect the complete body and final receipt before generating evidence.
`commit_reading`: work_dir, section_id, receipt, evidence. Runtime verifies the same source/range, commits once, advances contiguous offset and stores only paraphrases plus span/digest metadata. Identical replay is a no-op; changed replay fails. A truncated result is not a receipt. If a delivery is incomplete, reissue the same uncommitted range with smaller max_chars. Never commit an unseen terminal receipt copied from logs.
`lookup`: source and locator {entries,start,end,extractor,source_sha256}; returns text, ordered entry-local spans and receipt, bounded to 6,000 code points and 24,000 bytes. It requires exactly the recorded extractor and source. Offsets are NFC normalized Unicode code points in the concatenation of normalized entries, separated by one LF. This is not an entry-local #char value. Read and validation use this same path; no PowerShell InnerText substitute.
For UTF-8 TXT/Markdown/HTML the entry is document; DOCX entries are word/document.xml plus footnotes/endnotes when present; text PDF entries are page:1, page:2, etc. The helper preserves these entry identities and uses the same code-point mapping and receipts. PDF requires pypdf in the chosen Python environment; missing dependencies, encrypted PDFs or pages without text stop explicitly. Apply the source-adapter completeness checks for diagrams, rendered pages, tables, note coverage and OCR; text extraction alone does not prove visual or scanned-book completeness. Never coerce unsupported/OCR data into EPUB or reuse old extraction offsets.

## State, locking and transactions
Every mutating request uses the current expected_revision from `status`; stale concurrent requests fail. Runtime locks state for the duration of one command with an OS file lock released on process death. The parent separately prevents overlapping model workers.
`reading_view`: section_id and start; returns at most 6,000 characters of committed section metadata/evidence outside capture. `status` returns only identity, revision, stage, counts and the next four section offsets; it never returns evidence or answer keys. Identity includes source hash, edition and canonical three output paths; check it on every resume. `recover` rolls forward a validated journal with exact before/after hashes. It rejects external edits and never guesses.
`checkpoint`: work_dir, expected_revision, unit_id, category, payload. Category is derived, reconstruction, answers, score, verification or validation. IDs are immutable: the same payload is already-committed; a changed payload fails. It stores bounded paraphrases. Use one chapter reconstruction or up to four answer IDs per request. Score one predeclared slice; verification one question. Set the input source/plan digest inside payload when work depends on evidence.
`commit_files`: work_dir, expected_revision, unit_id, files [{target, content OR append, before_sha256}]. Targets must be inside the package or equal the authorized Agent path. before_sha256 is null for an absent file. The runtime journals exact candidates and a new state, then installs them atomically one file at a time and updates state. After a crash it adopts only the exact expected bytes and rolls forward. For long derived maps use append with one block of at most 6,000 characters; the helper reads prior bytes and builds the complete transaction candidate without exposing the whole file to the model. Use content only for a prepared full-file replacement. All source evidence and authoring outputs remain bounded per model tool result. Never regenerate an already committed block.
Each accepted semantic unit increments revision once. A recover/replay cannot duplicate a unit. A journal contains candidates, identities and hashes and is removed only after all files and state are installed. Source dumps are prohibited in request/state/output files.

## Questions and closed-book phases
`freeze_questions`: after all substantive sections are READ, provide exactly Q01-Q20 with prompt, expected_elements, evidence_class, locator, section_ids and affected_maps; reconstruction_units [{id,title}] including every substantive section plus a synthesis; score_plan [{id,component,max_points}] with totals 15/20/20/20/15/10 for structure, chapters, concepts, mechanisms, boundaries, actions. Freeze these bytes/digests before capture. Each question is <=1,500 characters. These fields are specifications, not proof of test quality.
`capture_view`: offset and limit (at most 4). Returns question IDs/prompts only, plus pending reconstruction IDs/titles and capture progress. No keys, locators or source evidence. Use `captured_view` for bounded already committed capture outputs. Author capture from retained understanding; disclose lost recall.
Capture checkpoints use category reconstruction with {id,text}, then answers with {answers:{Q01:text,...}}. Committing the first starts attempt 1. All planned reconstruction blocks and 20 answers must be durable before `begin_scoring` locks capture. Pass work_dir to factory lookup commands so capture-phase checks apply. Bounded evidence views are closed during capture. These are procedural capture controls, not OS access isolation; an independent model-session test must be reported separately.
Score checkpoints use {id,points,reason}; IDs and maxima come from score_plan. Verification uses {question_id,correct,reason,lookup_sha256,locator}. `evidence_view` is available only after capture is locked; it returns one question or one bounded reading-evidence slice.
`decide` requires all declared score slices and all 20 verdicts, computes totals and persists pass/fail. Correctness is the model's evidence-backed judgment, not a hash inference.
For authorized remediation, keep attempt 1 immutable and frozen questions/score criteria unchanged. `begin_remediation` requires current FAILED, attempt 1, explicit authorization string supplied by the user, and target Agent absent. Point-check failures and checkpoint repairs through commit_files. `start_attempt_2` requires a durable remediation-complete validation record covering every failed question/rubric dependency. Then recapture and rescore as attempt 2; no third attempt. Runtime records authority; it cannot independently authenticate a user's natural-language approval.

## Package and Agent finalization
`seal` requires PASSED and exactly eight expected package files. Verify source identity, coverage, concepts and map requirements as Agent checks before seal. The runtime verifies manifest hashes for the other seven files, captures all eight file hashes and marks SEALED. Package files become immutable through helper commands.
Write Agent TOML only after the NLPM gate via commit_files; a crash after file installation resumes from journal without overwriting a conflicting file. Parse and Doctor are separate validation checkpoints. Require the actual parser result and Doctor exit 0/config.load ok before ready-for-parent-canary.
Use `complete` only after durable validation records named toml, doctor and parent-canary each have passed=true; doctor has exit_code=0 and config_load=ok, and parent-canary has runtime_identity_verified=true and nonempty evidence. Record hashes and evidence in work state, preserving the sealed package.

## Legacy import and recovery
Do not auto-migrate version-1 files. For a stopped legacy run, first verify the old manifest/source/edition/paths and recorded READ-unit boundaries, prove the old worker stopped, and obtain authorization for its new WORK_DIR. Import only metadata and paraphrased evidence through a reviewed per-package adapter; refuse ambiguous schemas, uncommitted captures and old offsets without their exact extraction algorithm. Preserve originals and captured attempts byte-for-byte. Existing COMPLETE packages need no migration. If these checks cannot be established, report needs-input/validation-failed and preserve the old package rather than reread or reset it.

## Acceptance evidence
Use disposable fixtures for process termination after journal persistence, after individual file installation and after state installation. Recovery must reproduce uninterrupted expected bytes; replay must not advance revision twice. Test a long section across entries, non-BMP Unicode, truncated delivery, changed source, stale revision, invalid path, frozen capture and first/middle/last locator checks. These deterministic tests prove helper behavior; report model end-to-end canaries separately and never label fixture tests as a whole-book model reading.
