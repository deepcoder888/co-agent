# A-book protocol v3 — source-grounded creation

## Version and authority
Use Python 3.11+ synchronously:
`python -X utf8 -B ~/.codex/agent-support/a-book/abook_runtime_v3.py --request <absolute-request.json>`
Requests are UTF-8 JSON; `--request -` reads stdin through EOF. Store requests only in the authorized work directory. Exit 0 means the operation succeeded; exit 2 rejects a request; injected fixture crashes exit 86.
New state schema is 3, extractor abook-source-nfc-codepoints-v3.0, assessment profile GROUNDED_QA_V3. The model owns meaning and classification; hashes and receipts prove byte consistency, not understanding or actual model attention.
Old protocol.md and abook_runtime.py remain unchanged. Existing v2/legacy packages retain their original profile and history; resume with their bound runtime and instructions. Report legacy-runtime-unavailable if hashes differ. Migration requires a separate reviewed, authorized task.

## Scope and reading policy
1. Inventory every source entry, including navigation-only content, before the first reading unit.
2. Include the author's substantive main text, argument-bearing introductions/appendices/notes, explanatory tables/figures, and research or objections discussed as part of the argument.
3. Exclude only classified non-substantive material: endorsement (recommendations/praise), review (other people's evaluations of this book), promotion (advertising), acknowledgments, bibliography (citation-list-only spans), navigation, publication_metadata.
4. Preserve substantive third-party prefaces, editors' clarifications, and notes if they explain or qualify the book. A heading or the author's identity alone cannot justify exclusion. Retain uncertain passages.
5. Build a bibliography index by location/count or existing identifiers; no per-reference research or review synthesis. Keep substantive notes mixed into a references section. No web research, external fact-check pipeline, Word rendering or other reviewers' opinions during creation.
6. For mixed entries, record exact normalized excluded ranges, reason and kind. Inspect boundaries through bounded lookup; included and excluded ranges together cover the entire normalized text with no overlap.
7. Protected/missing/OCR-incomplete/visually unreadable substantive content is blocked-source. Time pressure is never an exclusion reason. Inspect argument-bearing images; decorative covers and advertising images need only classification.
Coverage means 100% of included author-substantive content, not every page of the source. Exclusions are visible in README, coverage ledger and final report.

## Budget and compact output
Plan 240 minutes: scope 10, reading 120, six maps 40, grounded QA/one repair 30, NLPM/Agent/Doctor/canary 25, buffer 15. These are scheduling targets; no empirical four-hour guarantee exists. The state records UTC creation time and status reports wall-clock elapsed time including pauses.
At preflight report source size, included/excluded character counts and image burden. During work report changed estimates at stage transitions. If elapsed time exceeds 240 minutes, preserve quality and checkpoints, state the overrun and finish the authorized work unless a caller hard limit requires yielding.
Keep each source/evidence tool result <=6,000 Unicode code points and <=24,000 serialized UTF-8 bytes. Request >=8,000 output tokens for source envelopes and inspect the last receipt. Use smaller max_chars after truncation.
Aim for source-unit evidence of 200-400 characters, extended only for definitions, equations or necessary conditions. Record proposition/mechanism, locator and uncertainty; omit empty template fields.
Six Markdown maps target 20,000 total Unicode characters:
- chapter-map.md: every substantive chapter's core proposition, argument chain, dependencies, conditions and locators (target 8,000).
- concept-map.md: exactly three core concepts, selection rationale, definitions and links (3,000).
- first-principles.md: premises and inferential structure with references to concepts, avoiding repeat explanation (2,500).
- retrieval-bank.md: Q01-Q20, concise answers, conditions and evidence locators (2,500).
- action-map.md: bounded applications, observations, stops and BOOK versus adaptation labels (3,000).
- README.md: exact identity, scope/exclusions, acceptance profile, navigation and limitations (1,000).
These are targets, not truncation limits. Explain any overrun in package-audit and retain essential evidence. The other two files are source-manifest.json and coverage-ledger.json, generated by the runtime. No derived block or entire long map should be regenerated solely because a session resumed.

## Inputs and state
All requests include op; state operations include work_dir. Mutations require the current expected_revision except init/recover. Package, work and Agent paths must be non-overlapping; targets must be absent at init.
State is WORK_DIR/state.json. journal.json is a transient transaction, never a competing authority. OS locks protect individual commands; the parent enforces one model worker. Confirm termination before resuming/replacing. Use the existing run identity, runtime hash and extractor. Retry only diagnosed, uncommitted work (at most twice), and stop after two invocations without semantic progress.
Mutating transactions preflight all target hashes, journal candidates, then install files/state. Explicit recover rolls forward only matching hashes. Identical immutable unit replay is a no-op; changed replay fails. Existing sealed packages and unrelated targets stay immutable.

## Source commands
inventory: source, optional offset>=0 and limit 1..20 (default 10). Iterate until both linear_total and navigation_total are covered; inventory exposes metadata, not prose.
lookup: source, locator {entries,start,end,extractor,source_sha256}; optionally work_dir to bind the current run. Offsets are NFC Unicode code points over the ordered entries joined by one LF, not byte/UTF-16 offsets. Source/extractor/hash must match. Returns text, entry spans, text_sha256 and final receipt. Lookup stays available throughout grounded answering and verification.
init: source, edition, package_dir, agent_path, work_dir, ordered sections, optional run_id/test_fixture. Each section has {id,title,entries,substantive,kind}; excluded sections also require reason. Included kind is content; excluded kind is one of the seven policy kinds above.
Optional agent_model and agent_reasoning_effort default to gpt-5.6-sol and xhigh; different values require a recorded model_override_authorization from the user. This override is bound into the run identity and checked against the installed Agent.
Included sections may contain exclusions [{start,end,kind,reason}]. Ranges are sorted, non-overlapping and inside normalized text. The runtime hashes excluded spans. Purely excluded sections automatically receive a full-range exclusion. Every linear entry is assigned exactly once in source order; nav-only substantive content is added explicitly.
read_unit: section_id, optional max_chars 1..6000; returns the next included range, stopping at an exclusion boundary. Commit before the next read. Classification lookups are not coverage.
commit_reading: section_id, receipt, evidence object, and the same max_chars if non-default. Evidence contains paraphrases and locators, never source dumps. The runtime advances only contiguous included coverage, skips recorded excluded ranges, and marks READ only when all included content is covered.
reading_view: section_id, start offset into the bounded serialized section evidence. status: identity, stage/revision, included coverage, exclusions, budget and question progress. recover: replay a pending transaction explicitly.

## Derived files and checkpoints
commit_files: unit_id and files [{target,content OR append,before_sha256}]. Targets are exact package filenames or the authorized Agent. Use <=6,000-character append blocks for prose; full replacement is for a prepared local repair. Retain existing source locators and references. During ANSWERING/VERIFYING evidence files are frozen; editing resumes only in REPAIR, or after a pass for final metadata.
checkpoint: unit_id, category (derived, validation, answers, verification), payload. Model checkpoints are <=24,000 serialized bytes. Unit IDs are immutable; answer/verification IDs are namespaced by assessment round.
Use input digests in derived payloads. A continuous invocation may perform any number of committed units within the actual caller/context budget; there is no two-unit handoff rule.
view_file: path and start, bounded to package text. Views, maps and source remain readable during QA. Answer keys are exposed only by evidence_view after answers freeze.

## GROUNDED_QA_V3
freeze_questions: questions exactly ordered Q01..Q20. Each question has:
{id,prompt,kind,expected_elements,evidence_class,evidence,affected_maps}.
Finish all six Markdown maps first. Their hashes freeze with the questions; changed maps invalidate QA outside the one repair phase. After a pass, only final metadata and the reviewed Agent can be written. Put the profile, scope and acceptance requirements in README before QA; the final ledger records the actual result.
kind is definition, dependency, mechanism, boundary or action; include all five. evidence_class is BOOK, INTERPRETATION, INFERENCE or CRITIQUE. expected_elements is 1..6 concise essential requirements; accept semantic equivalence and preserve necessary conditions. affected_maps is a nonempty list of Markdown map filenames.
evidence is a list of 1..4 {section_id,locator} objects. Each window lies wholly inside included, already read content of that section. Cover first/middle/last thirds of substantive section order (for fewer than three sections, cover every section). Questions and criteria freeze together; excluded material cannot become a test question.
The model prepares the questions, so this is an evidence-backed acceptance check, not an independent benchmark. Questions must test explanation, conditions and application, not recall of praise, names in recommendations or incidental phrasing.

question_view: offset, limit<=4; exposes prompt, kind, evidence windows and pending IDs, not expected_elements. Maps/source may be consulted openly. Prevent pretending this is closed-book memory.
Answer checkpoint: category=answers, payload={answers:{Q01:{text,lookups},...}}, <=4 answers.
Each lookup has {section_id,locator,text_sha256,receipt}, matching one frozen evidence window. Reopen every declared window via lookup and copy its verified digest/receipt. Answer text <=3,000 characters; retain uncertainty.
begin_verification requires all 20 frozen answers (or every required retest answer); locks their digest.
answer_view: id, optional start; bounded captured answer.
evidence_view: id, available only after answers freeze; returns frozen criteria/evidence.
Verification checkpoint: category=verification, payload={verdicts:[{question_id,correct,critical,reason,missing_elements},...]}, <=4. Recheck the source and answer criteria; the runtime revalidates the stored source receipts. Both correct and critical are booleans; critical implies incorrect. missing_elements is an array.
A critical error is a materially false central BOOK claim, invented supporting evidence, or a missing safety-critical action condition. Missing nonessential wording is not an error. Infrastructure failure remains pending, not correct/incorrect.
A correct verdict must have an empty missing_elements list. At retest start the changed map set must equal the repair record's declared files; unaffected maps retain their hashes.
decide: requires all 20 verdicts. Pass is >=18/20 correct with zero critical errors, status PASSED_GROUNDED. Closed-book reconstruction and six-component scoring do not run; closed_book_mastery=NOT_PERFORMED.

## One local repair
begin_repair is eligible only after round-1 FAILED, before sealing/Agent creation. It preserves the entire first round and selects all failed IDs plus up to three passed IDs ranked by a deterministic hash of the frozen question set and ID. Original creation authority covers this one repair; no repeated permission prompt.
Only failed questions' affected maps can be repaired. Keep all questions/criteria frozen. Retest samples check that the repair did not regress passed answers; preserve unsampled answers and verdicts.
Checkpoint validation unit repair-complete with {passed:true,failed_ids,repairs:[{question_id,action,reason,map_files}]}. Cover every failed ID. action is answer_only or maps_corrected; the latter lists committed changed maps and a reason. An answer-only error does not require a cosmetic map edit.
start_retest requires that record; begins round 2 with the runtime-selected required_ids. Capture/verify only those IDs, <=4 per checkpoint. No new whole-book read, full reconstruction, regrading unaffected answers or third round.
decide in round 2 requires every retested answer correct in addition to the overall >=18/20 and zero-critical rule. A failure is terminal assessment-failed; retain all evidence. Passing QA does not imply the other creation gates passed.

## Package and Agent gates
After a QA pass, checkpoint validation unit package-audit:
{passed:true,substantive_section_ids:[...],concepts:[three distinct names],chapter_locators_checked:true,figures_checked:true,conditions_checked:true,exclusions_checked:true,prose_overrun_reason:""}.
The model verifies these claims against the maps and source; the runtime checks coverage, count and declared checks. Supply an explanatory prose_overrun_reason if six maps exceed 20,000 characters.
prepare_manifest: unit_id. Requires the six Markdown maps and package-audit. Mechanically writes coverage-ledger.json (scope, included/excluded intervals, source receipts, QA profile/summary) and source-manifest.json (source/edition/runtime/paths, QA profile, seven hashes). JSON files need not be printed into model context.
seal: exact eight files, matching source and metadata hashes, current QA PASSED_GROUNDED and matching ledger. Sealed package becomes immutable; state proceeds to CREATE_AGENT.
Generated Agent rules bind the v3 helper and hash, require exact-source BOOK lookups and disclose scoped coverage and GROUNDED_QA_V3; never claim old closed-book mastery. Keep default model=gpt-5.6-sol, effort=xhigh, read-only sandbox, approval never, live web for user-requested/current external comparisons.
Before commit_files writes Agent TOML, checkpoint validation nlpm:
{passed:true,score:90..100,skills:[writing-agents,rules,conventions,conventions-codex,scoring],draft_sha256:<UTF-8 draft hash>,revision_count:N,findings:[...]}.
The factory must load all five complete skills, review the full draft in memory before creation, report the score formula/history and 90 threshold, then record the exact draft hash. No unsupported Claude tools field.
After installation, checkpoint validation toml {passed:true,model:"gpt-5.6-sol",model_reasoning_effort:"xhigh",agent_sha256:...}; verify actual fields (or recorded explicit overrides).
checkpoint doctor {passed:true,exit_code:0,config_load:"ok",evidence:...} from real codex doctor --json.
Run Doctor in a real PTY for terminal checks. If an inherited TERM=dumb is the sole failure while the PTY has terminal input/output, set TERM=xterm-256color only for that child invocation and retry once; retain both reports. Do not persist environment changes or reclassify unrelated failures as passes.
checkpoint parent-canary {passed:true,runtime_identity_verified:true,agent_sha256:...,evidence:...} from the actual fresh named-Agent invocation. Require first/middle/last exact-source windows, concept and bounded action response, source gaps/evidence labels and no file changes. A fixture or self-reported role name is not runtime identity.
complete requires all records, unchanged sealed hashes and matching installed Agent hash. Missing gates return ready-for-parent-canary or validation-failed. Retain validation in WORK_DIR only.

## Verification and maintenance
Use the sibling test_abook_runtime_v3.py with Python -B. Fixtures cover source exclusions, mixed entries, Unicode/boundary locators, order/receipt rejection, stale revisions, journal recovery/replay, frozen questions/answers, one repair plus retained answers, incomplete/critical rejection, and sealed output/Agent gates.
Fixtures prove deterministic behavior, not full-book understanding, named-Agent model behavior or a four-hour benchmark. Preserve legacy files and packages byte-for-byte during v3 maintenance.
